# Допуск при установке и принудительный чёрный список

## Определение

Полный цикл **supply-chain enforcement**: скан при установке → белый/чёрный список артефактов → при обнаружении угрозы в рантайме **отзыв прав** песочницы и блок вызова **менее чем за 2 секунды** без перезапуска агента (defenseclaw + OpenShell).

Без шага enforcement сканирование остаётся отчётом в CI, а вредоносный навык продолжает работать.

## Как это работает пошагово

1. **Admission** — skill-scanner / mcp-scanner (способ №27) → вердикт allow / deny / quarantine.
2. Разрешённый артефакт попадает в **белый список**; опасный — в **чёрный список** + карантин файлов на диске.
3. **Watcher** — повторное сканирование при изменении файла (rug-pull, локальная подмена).
4. **Enforcement** — sidecar отзывает capability у OpenShell; вызов навыка падает с ошибкой (<2 с).
5. **OPA/Rego** — единая политика на admission, guardrail proxy и sandbox.

## От чего защищает

- Вредоносный навык **после** прохождения CI, но до эксплуатации в рантайме.
- Повторное отравление артефакта на диске (rug-pull).
- Rogue-поведение скомпрометированного плагина через отзыв capabilities (ASI10, частично).

## От чего НЕ защищает

- Атаку **без** установки нового артефакта (чистый prompt injection в чат).
- Вредонос, уже в **первом** одобренном baseline без последующего изменения.
- Компрометацию **ядра** агента вне sandbox OpenShell.
