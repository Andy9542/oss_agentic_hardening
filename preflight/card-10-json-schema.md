# Карточка №10 — Валидация структуры ответа (JSON / Schema)

> Статус: **экспресс** (пилот нижней границы шаблона). Слой: Текст. Тип по файлу: В → **переопределён в поддерживающий** (см. §2).
> Верификация: механизм — общеинженерное знание; llm-guard JSON-scanner `[док]`.
> Ось §4: OWASP LLM Top 10 2025 / Agentic Top 10 2026.

---

## 1. Идентификация

Проверка, что вывод модели соответствует ожидаемой структуре (JSON-схеме): типы, обязательные поля, enum'ы, границы значений. **Важная развязка, которую файл слил:** это два разных механизма с разной точкой врезки —

- **Валидация** (post-model): сгенерировали → проверили по схеме → отклонили/повторили, если кривой. Гарантия вероятностная (модель может не попасть в схему, тратятся ретраи).
- **Constrained decoding** (pre/at-decode): модель структурно *не может* произвести не-схемный токен (outlines, JSON mode, grammar-constrained). Гарантия детерминированная на уровне формы.

Класс №10 в файле назван «валидация», но покрывает оба; в карточке различать, т.к. security-профиль у них разный.

## 2. Статус класса после Этапа 0

**Понижен до поддерживающего** (V4 лога). Сам по себе почти ничего не *защищает* — обеспечивает форму, а не безопасность содержания. Защитный эффект вторичен и почти весь реализуется через другие методы (§8). На карточку это влияет структурно: центр тяжести — поле 8, не поле 4.

## 3. Точка врезки и режим

Egress / post-model (валидация) либо at-decode (constrained). Режим: inline-reject для валидации, архитектурное свойство для constrained. Ни то, ни другое не смотрит на *семантику* значения — только на его форму.

## 4. Модель угроз

**Закрывает (узко):** malformed-вывод, ломающий downstream-парсер; неограниченную строку там, где ожидался типизированный/enum-слот (сужает поверхность LLM05 Improper Output Handling — модель не вставит произвольный markdown/HTML/команду в поле, объявленное как `enum` или `integer`).

**НЕ закрывает (широко):** prompt injection; семантически валидное-но-вредоносное значение (схема пропустит `"recipient": "attacker@evil.com"` — это валидная строка); экфильтрацию через разрешённые поля; любое злоупотребление в рамках корректной формы. Схема проверяет *форму*, не *намерение* и не *происхождение*.

## 5–9. Схлопнутые поля (нижняя граница шаблона)

Для поддерживающего метода эти поля вырождаются в одну строку каждое — это и есть калибровочный результат:

- **§5 Обходы:** обход не нужен — атака просто соблюдает схему. «Слепая зона» = вся семантика.
- **§6 Цена:** низкая (валидация) / оверхед декодера (constrained); ретраи при непопадании в схему — единственный операционный налог.
- **§7 Реализации:** llm-guard (JSON-scanner) `[док]`; pydantic/JSON Schema (валидация); outlines/guidance/JSON mode (constrained) `[док]`.
- **§9 Проверочный протокол:** тривиален — подать не-схемный вывод, убедиться в reject. Атаки как таковой нет; hands-on не требуется.
- **§8 — НЕ схлопывается, вынесен отдельно ниже** (несущее поле для этого класса).

## 8. Сочетаемость — несущее поле

Вся реальная ценность №10 здесь. Структурированный, типизированный вывод — это **предпосылка** для методов, которые действительно защищают:

- **→ №19 (проверка аргументов tool-call):** нельзя валидировать аргументы, если они не в предсказуемой структуре. №10 даёт форму, №19 — смысл.
- **→ №16 (IFC/capability) и №12 (политики):** policy engine читает типизированные аргументы; произвольный текст политикой не покрыть. №10 — субстрат, на котором работают №12/№16.
- **→ constrained decoding как анти-инъекционный примитив:** если поле объявлено `enum`, инъекция физически не может вставить туда команду — здесь №10 переходит из «гигиены» в слабую, но настоящую защиту.

Правило калибровки: **у поддерживающего метода поле 8 несёт ту нагрузку, которую у настоящей защиты несёт поле 4.**

## 10. Вердикт

Как самостоятельная защита — покрытие **L**, устойчивость **L** (обходится соблюдением схемы), цена **L**. Как гигиена и множитель — **adopt безусловно**: дёшево, и без него не стоят №12/№16/№19. Позиция: `adopt` в роли enabler, `hold` в роли «защиты от инъекций» (ею не является).

## 11. Сценический тезис

> «Самый недооценённый элемент — не защита сама по себе. JSON Schema не остановит ни одной инъекции. Но без типизированного вывода у вас нет входа для policy engine и валидации аргументов — то есть половина слоя "Действие" держится на этой скучной гигиене. Плюс один нюанс: `enum`-поле — это бесплатный анти-инъекционный примитив, потому что в него нельзя вписать команду.»

## 12. Кандидат в демо/пример

**Пусто.** Самостоятельного визуала нет — метод не «показывается», он подразумевается. Корректный результат для поддерживающего класса: на сцене — одна строка в общей карте слоёв, не отдельный акт. (Незаполненное поле 12 = сигнал «карта, не демо», а не пробел карточки.)
