# Progent — SMT и монотонные политики

## Репозиторий

[sunblaze-ucb/progent](https://github.com/sunblaze-ucb/progent) — исследовательский проект UC Berkeley.

## Где в коде

- Точка входа: `check()` между решением модели и исполнением инструмента
- Решатель **Z3** для проверки монотонности обновлений политики
- Генератор политик на базе LLM — начальный и уточняющий контур

## Алгоритм (подробно)

1. Пользователь формулирует задачу → LLM генерирует **начальную политику** (DSL Progent): какие tools, какие ограничения на аргументы.
2. Агент предлагает `tool_call(name, args)`.
3. **check()** сверяет вызов с текущей политикой → разрешить / запретить / запросить одобрение человека.
4. При **уточнении** политики (новые данные из среды) Z3 проверяет: новое множество разрешений ⊆ старого (**сужение**) ИЛИ это **расширение** с флагом «только с одобрением».
5. Расширение без одобрения **отклоняется формально**, не эвристикой.

## Детерминизм или машинное обучение

- Проверка вызова и SMT — **детерминированные**
- Генерация политики — **LLM** (качество стартовой политики критично)

## Доказательная база

`source-progent-paper`: ASR на AgentDojo ~40% → ~1%.
