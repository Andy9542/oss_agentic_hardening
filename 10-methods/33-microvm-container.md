# Песочница: microVM и контейнеры

## Определение

Код и среда агента выполняются в **изолированной** виртуальной машине (Firecracker) или контейнере с отдельным сетевым пространством имён. После сессии среда **уничтожается** — не остаётся персистентного вредоноса.

## Как это работает пошагово

1. **create** — поднять microVM (отдельное ядро Linux) или контейнер.
2. **execute** — передать код/команды агента внутрь.
3. **ограничить egress** — только whitelist доменов или без сети.
4. **read** результат из изолированной среды.
5. **destroy** — удалить ВМ; секреты хоста недоступны при корректной конфигурации.

E2B: оркестратор → Firecracker VMM → демон envd внутри гостя; холодный старт ~125 мс (с E2B Cloud).

## От чего защищает

- Компрометация **хоста** через сгенерированный код.
- Lateral movement к соседним процессам.
- Персистентность после атаки.

## От чего НЕ защищает

- Легитимный перевод денег через **разрешённый** банковский API внутри песочницы.
- Prompt injection → вредное **разрешённое** действие.
- CVE escape из hypervisor (редко, критично).
