# SkillTotal — локальный сканер AI-компонентов

## Репозиторий

https://github.com/pezhik/skilltotal

## Где в коде

- `skilltotal/` — CLI и статический движок.
- `docs/architecture.md` — архитектура анализатора.
- `tests/` — автоматические тесты; `tests/manual_eval/` — ручная калибровка.
- GitHub Action и SARIF-вывод — CI-gate для репозитория.

## Алгоритм

1. Принимает локальный путь, Git URL, архив, отдельный файл или пакет `npm:` / `pypi:`.
2. Не исполняя компонент, применяет regex-правила и AST-анализ к skills, MCP-серверам, пакетам и проектам.
3. Строит evidence-anchored findings: файл, диапазон строк и фрагмент кода.
4. Выделяет опасные возможности, prompt-injection поверхности и возможные цепочки эксфильтрации.
5. Поддерживает baseline и diff двух версий; `guard` формирует решение перед установкой.
6. Выдаёт terminal, JSON или SARIF и может блокировать CI по severity или score.

## Детерминизм или машинное обучение

Статический движок полностью детерминирован: regex + AST, без LLM и без исполнения проверяемого кода. Registry provenance — дополнительный контекст и не влияет на основной verdict.

## Внешние зависимости

Python 3.10+; `git` нужен только для удалённых репозиториев. Основной движок заявлен без runtime-зависимостей и работает локально/offline. Сетевой доступ требуется для Git URL и registry provenance.

## Сигналы качества

- Тесты в репозитории: `pytest`, CI, manual-eval fixtures.
- Документированные обходы: неизвестные API и семантические цепочки вне набора правил; это не pentest и не runtime-контроль.
- Зрелость: PyPI, GitHub Action, SARIF, baseline/diff; проект молодой, независимый benchmark не указан.

## Вердикт

**экспериментально** — функционально целостный локальный сканер с хорошей эксплуатационной обвязкой, но слишком молодой для статуса проверенного production-барьера.
