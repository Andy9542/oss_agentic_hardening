# 02. Описание (description)

## Что считается «описанием»

«Описание» в карточке — не маркетинговый текст, а **минимально достаточное содержание**, чтобы метод был идентифицируем, сопоставим с угрозами и вошёл в справочник/доклад:

| Поле | Функция описания | Обязательность |
|------|------------------|:--------------:|
| §1 | Что это, из чего состоит, внутренние развязки | Всегда |
| §2 | Статус после Этапа 0 (подтверждён / понижен / расщеплён…) | Всегда |
| §3 | Где и как врезается в пайплайн | Всегда |
| §4 | Закрывает / **НЕ закрывает** (зеркало) | Всегда; **несущее** у защитных классов |
| §5–§7 | Обходы, цена, реализации | Полная карточка; схлопнуто у экспресс |
| §8 | Сочетаемость; **несущее** у поддерживающих | Всегда |
| §9 | Проверочный протокол | Полная; одна строка у экспресс |
| §10 | Вердикт (оси + radar) | Всегда |
| §11 | Сценический тезис (1–2 предложения) | Всегда |
| §12 | Демо-кандидат (отдельно от тезиса) | Всегда (может быть «пусто») |

Handoff даёт **указания к описанию** для ещё не написанных карточек, но не заменяет поля §1–§12.

## Покрытие описания в handoff (ещё не написанные карточки)

Handoff для 17+ пунктов даёт **скелет описания**, но не готовый текст:

| Что есть в handoff | Чего нет |
|--------------------|----------|
| Класс, тип карточки, несущее поле (прогноз) | §1 декомпозиция |
| Якоря и маркеры верификации | §4 зеркало «НЕ закрывает» |
| Границы с соседними № | §5–§9 (кроме указаний «схлопнуть») |
| Запреты на оверклейм | §10–§12 |

**Исключения с повышенной готовностью описания** (можно писать сразу по handoff + Stage 0):

- №12, №26, №44 — но с override Stage 0 по SMT / agentseal / YARA.
- №28, №34 — полные карточки с риском оверклейма; якоря сильнее среднего.
- №46* — **описание отсутствует**; нужен отдельный research pass (AgentPoison, ASI06).

## Сравнение глубины описания: экспресс vs полная

| Элемент | Экспресс (№2, №10) | Полная (№16) |
|---------|-------------------|--------------|
| §5 обходы | 1 строка / абзац | Раздел с 4+ слепыми зонами |
| §6 цена | 1 строка | Параграф + измеримые числа с пином |
| §7 реализации | inline-список | Таблица с маркерами |
| §9 протокол | «тривиален» / одна атака | 2 обхода + статус hands-on |
| Несущее поле | §4 (детективный) или §8 (поддерживающий) | §4 (+ архит. №43) |

Оба режима **описаны рамкой** через эталоны — исполнитель видит нижнюю и верхнюю границу.

## Вердикт по описанию

| Критерий | Оценка |
|----------|--------|
| Стандарт «что писать» есть | **Да** (template + эталоны) |
| Два эталона по глубине | **Да** (№10 экспресс, №16 полная) |
| Первая рабочая карточка батча 1 | **Да** (№2) |
| Описания для всех 22 пунктов | **Нет** — только handoff-указания |
| Единообразие §4 (OWASP) | **Нет** — errata не применена к №10/№16 |

## Рекомендации автору карточек

1. Копировать **глубину**, не **текст**: экспресс — по №10/№2; полная — по №16.
2. §4 всегда с пином Agentic 2026 / LLM 2025; сверять теги со Stage 0 §B.
3. «НЕ закрывает» обязателен — без зеркала карточка не проходит DoD.
4. Числа только с пином версии (урок CaMeL 67%→77%, Progent v1→v3).
