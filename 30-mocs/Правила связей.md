# Правила связей

Мета-документ: **не добавляйте на него wikilink** из заметок способов и реализаций — иначе появится лишний хаб на графе.

> **Примечание после объединения веток.** В vault сосуществуют две схемы имён файлов способов: нечётные (№ 1, 3, … 45) — русские имена (например, `01-классификация-инъекций-машинным-обучением`), чётные (№ 2, 4, … 46) — английские (например, `10-json-schema-constrained`). Правила ниже применимы к обеим схемам; примеры даны в английской.

## Цель

Граф должен показывать **откуда что взято** и **кто что реализует**, а не паутину «способ дополняет способ». Семантика «дополняет / требует / не заменяет» хранится в YAML и тексте **без wikilink**.

## Три типа связей (wikilink)

| Тип | Направление | Где |
|-----|-------------|-----|
| **Навигация** | MOC / Home → способ | `30-mocs/`, сводные таблицы |
| **Происхождение** | Источник → способ | `40-sources/`, раздел «Связи» |
| **Каталог → способ** | `repo-NN` → способ | `20-implementations/repo-*.md`, раздел «Реализуемые способы» |
| **Каталог → семейство** | `repo-NN` → `cluster-*` | поле `clusters:` и таблица в карточке |
| **Деталь → каталог** | `detail/*` → `repo-NN` | `20-implementations/detail/`, раздел «Связи» |

**Запрещено:** прямые wikilink между двумя `repo-*` (родственники — только через `cluster-*`).

Семантика «дополняет / требует / не заменяет» хранится в YAML и тексте **без wikilink**.

## Что не делать

- Wikilink между двумя заметками из `10-methods/` (ни в тексте, ни в `[[...]]` внутри YAML).
- Wikilink из способа на реализацию или источник — таблица Dataview и поле `sources:` достаточны.
- Wikilink на этот файл.

## Семантика без графа

В frontmatter способа — **имена файлов без скобок**:

```yaml
complements:
  - 01-ml-injection-classifier
requires:
  - 33-microvm-container
not-replaces:
  - 43-dual-llm-quarantine
sources:
  - source-garak-encoding-probes
covers:
  - ASI02
  - LLM06
```

Поле `covers:` — только **ASI01**…**ASI10** и **LLM01**…**LLM10** ([[MOC — Матрица угроз]]); без собственных кодов vault.

В тексте разделов «Дополняет», «Требует», «Не заменяет» — **«способ №N (краткое имя)»**, не `[[wikilink]]`.

В поясняющем тексте тела заметки — тоже «способ №N», если ссылка не навигационная.

## Реализации

Три уровня в `20-implementations/`:

| Уровень | Файл | Связь на графе |
|---------|------|----------------|
| **Каталог** | `repo-NN-slug.md` | → все реализуемые способы, → cluster(s), → detail |
| **Деталь** | `detail/*.md` | → родительский `repo-NN` (Связи); `method-id` в YAML |
| **Вне каталога** | `detail/*.md` без `parent-repo` | → способ (Связи) |

- Каталог: `type: repo-catalog`, `catalog-id`, `clusters:` (список), wikilink на каждый способ в «Реализуемые способы»; `method-id` — основной, `also-method-ids` — остальные.
- Деталь: `type: implementation-detail`, `parent-repo: repo-NN-slug`, одна wikilink на каталог.
- Список в заметке способа — через Dataview по `method-id` и `also-method-ids`.

## Источники

- Поле `sources:` в frontmatter способа — список имён файлов из `40-sources/`.
- В заметке источника — wikilink на способы, для которых он дал доказательства (раздел «Связи»).

## Фильтр графа Obsidian

**Ядро (только способы и MOC):**
```
-path:20-implementations -path:40-sources -path:90-templates
```

**Каталог 100 + семейства (без деталей):**
```
path:20-implementations (file:repo- OR path:30-mocs/cluster-) -path:20-implementations/detail -file:*-methods
```

**Полная цепочка одного репозитория:** `repo-NN` → способы; соседи также через `cluster-*` и `detail/*`.

## Сироты

- Каждый способ входит в свой навигационный MOC: чётные — [[MOC — Чётные способы]], нечётные — [[MOC — Нечётные способы]].
- Каждая реализация имеет `method-id` и wikilink: каталог → способы (раздел «Реализуемые способы»), деталь → каталог.
- Каждый источник, используемый в `sources:`, ссылается обратно на способы.
