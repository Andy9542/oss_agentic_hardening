# 03. Примеры и демо (§12)

## Что считается «примером»

В preflight «пример» — это не обязательно готовый скриншот или репозиторий. По стандарту v1.1:

- **§12 «Кандидат в демо/пример»** — текстовое описание визуала или сценария hands-on;
- значение **«Пусто»** — легитимный и информативный ответ (правило К3);
- отдельно **§9** может требовать протокол атаки без готового артефакта;
- **§11** (тезис) не заменяет демо.

Отсутствует: централизованный банк готовых артефактов (JSON-схемы, D3-графы, трейсы OTel, скриншоты AgentDojo).

## Калибровка «пусто» vs «есть»

| Сигнал §12 | Смысл для доклада | Смысл для матрицы |
|------------|-------------------|-------------------|
| **Пусто** | Метод в общей карте слоёв, не отдельный акт | колонка «демо» = нет |
| **Есть (standalone)** | Приоритетный пул демо C8 | колонка «демо» = есть |
| **Есть (контраст-кадр)** | Показывает силу и потолок метода | колонка «демо» = есть |

Правило из №10: *«незаполненное поле 12 = сигнал „карта, не демо“, а не пробел карточки»*.

## Примеры в готовых карточках

### №10 — §12 = **Пусто** (намеренно)

| Элемент | Содержание |
|---------|------------|
| Демо-артефакт | Нет |
| Обоснование | Поддерживающий enabler; визуал не продаёт класс |
| Альтернативный «пример» в тексте | §1 различает validation vs constrained; §8 даёт связки → №12/№16/№19 |
| Достаточно для конвейера? | **Да** — эталон нижней границы |

**Потенциальный микро-пример** (не в карточке): side-by-side JSON с лишним полем → reject vs `enum`-поле, куда инъекция не влезает. Опционально для постера, не обязателен для DoD.

### №16 — §12 = **Есть, сильный визуал**

| Элемент | Содержание |
|---------|------------|
| Статичный слайд | Флоу-граф трифекты: private data + untrusted web → `send_email` → policy gate красный |
| Живой вариант | Трейс меток AgentDojo: untrusted value → сетевой tool → блок |
| Контраст-кадр | Тот же сценарий на текстовом фильтре №1 проходит, на IFC — нет |
| Зависимости | D3/постер-конвейер из EA-обзора; AgentDojo как бенчмарк |

**Внешний якорь:** CaMeL решает 77% задач AgentDojo с доказуемой безопасностью vs 84% без защиты [1] — число для тезиса, не замена визуала.

### №2 — §12 = **Есть (standalone)**

| Элемент | Содержание |
|---------|------------|
| Кадр A | Indirect PI прошёл №1, пойман AlignmentCheck по рассинхрону плана |
| Кадр B | Тот же кейс с «faithful-looking» прикрытием — проходит |
| Зависимости | D3/постер-конвейер; трейс assistant-role для AlignmentCheck [2] |

**Внешний якорь:** AlignmentCheck — few-shot CoT-аудитор, флаги goal hijacking [2]; в AgentDojo снижает ASR с 0.18 до 0.03 (Llama 4 Maverick backend) [2].

## Пробелы в «примерах» как артефактах

| Пробел | Влияние | Что делать |
|--------|---------|------------|
| Нет папки `examples/` с JSON/YAML/трейсами | Демо остаются текстовыми намерениями | По мере §9 hands-on складывать в `experiments/` |
| Нет единого D3-шаблона флоу-графа | №16/№28 зависят от «постер-конвейера» | Переиспользовать EA-обзор или завести `assets/flows/` |
| §9 `[не выполнено]` у №16 и №2 | На сцене нельзя говорить «мы проверили» | experiments-todo |
| №10 без визуала | Норма для enabler | Не требовать демо retroactively |
